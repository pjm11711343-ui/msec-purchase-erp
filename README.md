명신기공 구매관리 ERP — 1~5단계 (기준정보·청구·결재·발주·입고·계산서 매칭·투입집계)
=====================================================================

이번 단계에서 되는 것
- 로그인 (사내: 아이디 또는 이메일), 역할별 메뉴 (관리자 / 자재부 / 현장소장 / 현장담당)
- 기준정보: 현장, 업체, 분류(표준분류 연결), 단가 조회(단가관리시스템 읽기 전용), 사용자, 결재선, 설정
- 청구서 파일 이관: 현장별 청구서 엑셀 → 현장 정보, 투입집계 분류·금액(시작 잔액), 업체
- 계산서: 월 계산서정리 엑셀(업체별) 업로드 → 현장·분류별 저장, 기준월 이후 월은 투입원장에 반영
- 투입집계: 현장별 도급/변경예상/실행/투입, 월별 투입, 실행 대비 투입률, 엑셀 다운로드
- 대시보드: 현장별 투입률 카드

2단계 (구매청구·결재)
- 구매청구 > + 청구서 작성: 현장·결의번호·사용 목적, 품목 직접 입력 / 엑셀 붙여넣기 / 기존 청구서 엑셀 불러오기
- 단가 자동: 단가관리시스템 구매단가(거래선 단가 우선, 없으면 최저가) → 직전 발주단가 → 직접 입력, ▾ 버튼으로 후보 비교
- 기반입: 같은 현장 승인된 청구의 금회청구 누적 (엑셀로 받은 기반입이 있으면 그 값부터)
- 결재선: 현장 기본값(기준정보 > 결재선) 자동, 청구서마다 2단계/6칸·결재자 변경 가능
- 결재함: 내 차례 청구서, 승인/반려(사유 필수), 결재 회수, 자재부 단계에서 거래선·발주수량·단가 수정
- 원 양식 열 배치로 엑셀 다운로드

3단계 (발주)
- 발주 > 발주 대기: 최종 승인된 청구 품목이 현장·거래선별로 묶여 나옴, 거래선 없는 줄은 여기서 지정
- 체크한 줄로 발주서 만들기 → 현장·거래선마다 한 장, 발주번호 현장코드-YYMMDD-순번 자동
- 발주서 화면: 원 양식(A4) 그대로 인쇄 / PDF 저장(인쇄 창에서 'PDF로 저장'), 엑셀, 메일 제목·본문 복사, 발송 완료 표시
- 단가 표시 끄기(업체에 단가 없이 보낼 때), 내부 결재란(6칸) 표시
- 발주 취소 시 품목은 다시 발주 대기로 돌아감, 취소된 발주서는 관리자가 삭제 가능
- 구매청구서 줄마다 발주번호가 표시됨

4단계 (업체 포털 · 입고)
- 기준정보 > 업체: 업체 한 곳 체크 → '포털 접속코드 발급' → 업체코드(V001…)와 8자리 접속코드가 한 번만 표시됨, '안내 문구 복사'로 업체에 전달
- 재발급하면 새 업체코드가 나오고 이전 코드는 막힘, '포털 접속 막기'로 즉시 차단
- 업체: 로그인 화면 '협력업체' 탭(주소 끝에 /?vendor 를 붙이면 바로 열림) → 자기 업체 발주서만 보임
  · 발주 확인 버튼, 발주서 보기/인쇄, 현장 입고일·수량 입력(줄 선택 또는 '남은 수량 전체 입고'), 분할 납품 가능
- 사내: 입고 현황 메뉴 — 발주서별 입고율(미입고/부분입고/입고완료), 업체 대신 입력(대리), 현장 확인, 입고 기록 엑셀
- 보안: 업체 계정은 자기 업체 발주서·입고만 읽고, 발주서는 '발주 확인'만 바꿀 수 있음
- 업체 포털을 외부에서 쓰려면 Vercel 등에 배포해야 함 (README 6번)

5단계 (계산서-발주 매칭 · 업체 거래명세서)
- 계산서 업로드 시 기준월 이후 월은 자동매칭: 업체+현장+품명+규격으로 발주·입고를 찾아 연결
  · 미발주(발주 없음) / 수량초과(입고보다 많이 청구) / 단가차이(발주단가와 1원 넘게 차이) / 미입고 로 표시
  · 현장분류가 비어 있으면 발주 줄의 분류를 그대로 가져옴
- 계산서 목록 '발주 매칭' 열(매칭 줄/전체) → '매칭' 화면에서 줄마다 발주 직접 선택, 문제를 확인했으면 '인정'
- 저장하면 그 계산서의 투입원장이 현장분류 기준으로 다시 계산되어 투입집계에 바로 반영
- 업체 포털 '거래명세서' 탭: 월·현장을 고르면 아직 청구 안 한 입고 기록이 나옴 → 체크 후 제출 (반영 전엔 제출 취소 가능)
- 사내: 계산서 목록에 '업체 제출' 표시 → 매칭 화면에서 '확인 후 투입원장 반영'
- 엑셀 날짜가 하루 당겨 읽히던 문제 수정 (7월 계산서는 다시 올려 날짜 보정 완료)


1. 준비물
---------
- Node.js 20 이상 (https://nodejs.org 에서 LTS 설치)
- 기존 단가관리시스템의 Firebase 프로젝트 (같은 프로젝트에 붙입니다)


2. Firebase 설정
----------------
0) 이미 설정돼 있다면(src/config/firebase-config.json 에 값이 있음) 이 단계는 건너뜁니다. 실행은 ERP실행.bat 더블클릭.
1) 이 폴더의 .env.example 파일을 복사해서 이름을 .env 로 바꿉니다.
2) Firebase 콘솔 > 프로젝트 설정 > 일반 > 내 앱 에서 단가관리시스템이 쓰는 웹앱 설정값을 .env 에 붙여 넣습니다.
3) VITE_PRICE_COLLECTION 에 단가관리시스템이 단가를 저장하는 Firestore 컬렉션 이름을 넣습니다.
   (모르면 Firebase 콘솔 > Firestore 에서 단가 데이터가 들어 있는 컬렉션 이름을 확인)
4) Firebase 콘솔 > Authentication > 로그인 방법 > "이메일/비밀번호" 를 사용 설정합니다.
   (아이디 로그인도 내부적으로는 이메일/비밀번호 방식입니다. 아이디 홍길동 → hong@msec-erp.local)


3. 실행
-------
명령 프롬프트(또는 PowerShell)에서 이 폴더로 이동한 뒤:

  npm install
  npm run dev

브라우저에서 http://localhost:5173 을 엽니다.


4. 보안 규칙 합치기 (중요)
--------------------------
firestore.rules 파일을 그대로 배포하면 단가관리시스템 규칙이 지워집니다. 반드시 합쳐서 넣으세요.

1) Firebase 콘솔 > Firestore Database > 규칙 탭을 엽니다.
2) firestore.rules 에서 "===== ERP 시작 =====" 부터 "===== ERP 끝 =====" 까지를 복사합니다.
3) 기존 규칙의  match /databases/{database}/documents {  바로 아래 줄에 붙여 넣고 "게시" 합니다.
4) ERP 사용자가 단가를 읽을 수 있게, 기존 단가 컬렉션 규칙에 다음 조건을 추가합니다.
     allow read: if isOffice();
   예) match /prices/{id} { ...기존 규칙... allow read: if isOffice(); }
5) 붙여 넣은 뒤 콘솔의 "규칙 플레이그라운드"로 erp_sites 읽기를 한 번 시험해 보세요.


5. 처음 사용하는 순서
---------------------
1) 로그인 화면 아래 "처음 설치했나요? 최초 관리자 만들기" → 관리자 계정 생성 (한 번만 가능)
2) 기준정보 > 설정 : 이관 기준월 2026-09, 현장코드 접두어 MS 확인
3) 이관 > 청구서 파일 이관 : 현장별 청구서 엑셀을 한꺼번에 선택
   - 기계/소방 블록이 나뉜 파일은 블록마다 "새 현장으로"가 따로 잡힙니다 (예: 다산 지금(기계), 다산 지금(소방))
   - 공종이 잘못 추정됐으면 블록 옆 드롭다운으로 바꾼 뒤 저장 (예: 용인원클러스터 → 소방)
   - 같은 파일을 다시 올리면 "기존 현장에 덮어쓰기"로 잡혀 금액만 새 값이 됩니다
4) 기준정보 > 분류 : "표준분류 초안 만들기" → 이름이 같은 분류끼리 자동 연결
   - 비슷한데 따로 잡힌 표준분류는 오른쪽 "관리 > 다음으로 합치기"로 합칩니다
   - 미지정 분류는 체크해서 한꺼번에 연결합니다
5) 계산서 : 월 계산서정리 엑셀(업체별)을 선택
   - 이름에 "거래명세서"가 들어간 시트만 읽음 (현장별 정리 시트는 읽지 않음)
   - 시트마다 ERP 현장을, 분류마다 현장분류를 확인 (노란칸 = 직접 골라야 함)
   - 한 번 고른 표기는 기억해서 다음 달부터 자동으로 잡힙니다
   - 기준월(2026-09) 이전 월은 "기록만 저장" — 투입금액이 이미 시작 잔액에 들어 있기 때문
6) 기준정보 > 사용자 : 현장소장·현장담당 계정 만들고 담당 현장 체크
7) 기준정보 > 결재선 : 회사 기본값과 현장별 결재선(2단계 / 6칸) 지정


6. 배포 (Vercel)
----------------
1) GitHub 저장소에 올리고 Vercel 에서 Import
2) Vercel 프로젝트 Settings > Environment Variables 에 .env 값을 그대로 등록
3) Firebase 콘솔 > Authentication > 설정 > 승인된 도메인 에 Vercel 주소 추가
vercel.json 이 들어 있어 새로고침해도 화면이 유지됩니다.


7. 파서 확인 (선택)
-------------------
엑셀 양식이 바뀌었을 때 화면 없이 읽기 결과만 확인할 수 있습니다.

  npm run test:parsers -- "엑셀파일이 있는 폴더"


데이터 구조 (Firestore, 모두 erp_ 접두어)
------------------------------------------
erp_users            사용자 (문서 id = 로그인 uid)
erp_sites            현장
erp_vendors          업체
erp_standardCategories 표준분류
erp_siteCategories   현장분류 (도급/변경예상/실행/이관 투입금액)
erp_inputLedger      투입원장 (기준월 이후 계산서 금액, 현장분류·월별)
erp_invoices         계산서 (월_업체_현장 단위, 줄 내역 포함)
erp_approvalLines    결재선 (문서 id = 현장 id, _default = 회사 기본값)
erp_settings         main(설정), bootstrap(최초 관리자 기록)
erp_auditLogs        변경 기록
erp_requisitions     구매청구서 (결재 단계 포함)
erp_purchaseOrders   발주서
erp_receipts         입고 기록
erp_vendorAccounts   업체 포털 계정 (업체코드)
